## 1️⃣ 要做什么

### 可行性结论

四项需求均可在当前最低 iOS 17 的工程内实现，不需要提高最低系统版本，也不需要新增后台运行能力、服务端或第三方依赖。这里的防误触是应用内触摸保护；常亮是阻止无操作导致的自动休眠。

| 需求 | 结论 | 实现路径 |
| --- | --- | --- |
| 去掉实时活动与后台续跑 | 可行 | 当前没有自建 ActivityKit/Widget 实时活动目标。系统实时活动来自 `ContinuedTrackingSession` 提交的 `BGContinuedProcessingTask`；删除整条后台任务链路及配置。 |
| 头追开始后显示防误触入口；进入后全屏覆盖并常亮 | 可行 | `tracking == true` 时显示独立按钮。根层蒙层覆盖安全区和导航栏、拦截触摸；进入时设置 `UIApplication.shared.isIdleTimerDisabled = true`。 |
| 中央按钮长按 1.5 秒取消 | 可行 | 统一使用 `TouchGuardState.unlockDuration = 1.5` 判定触摸时长，系统图层动画绘制边框进度；松开、取消或移动超出允许范围后重置。 |
| 无操作三秒降亮度，操作恢复 | 可行 | 用当前窗口 `windowScene.screen.brightness` 保存、设置和恢复真实亮度；按下即恢复，触摸结束后重新计时。 |

### 验收标准

- [ ] 开始/重新校准头追不再提交持续后台任务，不再生成该任务的实时活动。
- [ ] 未开始头追时无防误触入口；成功开始后显示“防误触”按钮，点击才进入保护。
- [ ] 保护层覆盖整个应用页面。底层滚动、参数滑块、停止、连接/断开、回中、翻转和错误提示关闭按钮不可通过蒙层触发；辅助功能焦点也不进入底层。
- [ ] 保护期间头追采样、控制和现有断连停机检测继续执行；常亮只在保护期间开启，退出恢复先前设置。
- [ ] 中央显示紧凑的“取消防误触”按钮，进度沿按钮边框从顶部顺时针填充；不显示“长按 3 秒取消”及“头追持续运行，屏幕保持常亮”文案。连续长按达到 1.5 秒才退出，普通点击、连续短按、未满 1.5 秒松开均不退出。
- [ ] 进入保护或最后一次触摸结束后三秒开始用约一秒平滑降亮度；按下任意应用内位置立即中断过渡、恢复降亮度前的数值；持续按住/拖动期间不降亮度，最后一个触点结束后重新计时。
- [ ] 中央按钮当次触摸即可恢复亮度并开始长按，无需先额外点一次唤亮；取消成功的同一触摸序列不得触发底层按钮。
- [ ] 头部运动、姿态更新和相机消息不算屏幕操作，不重置三秒计时。耳机/相机异常使头追停止时，同时退出保护、恢复显示设置并展示现有错误。
- [ ] 取消防误触后头追继续运行，用户可回原页面停止；防误触不代替停止头追。

### 建议默认值与范围

- 降亮度建议上限为 `0.05`，使用 `min(降亮度前亮度, 0.05)`，避免原亮度更低时反而变亮。这是建议值，用户尚未指定具体亮度。
- “操作”按应用内触摸定义，包含按下、移动、松开和取消；不包含头部运动、姿态消息和音量键。
- 持续按住算正在操作，最后一个触点结束后才开始无操作计时，避免长按过程中触发无操作降亮度。
- 不做后台/锁屏续跑适配。建议仅保留进入后台时停机并释放显示设置的最小清理；返回前台沿用连接/传感器启动入口，需重新校准才能继续头追。临时 `.inactive` 不直接当作后台停机，以免权限弹框等造成误停。

- `PocketHead/HeadphoneMotionService.swift`：`onSample` 仅供后台补偿节奏使用；删除该接口和调用，保留主循环读取 `latestSample`、耳机连接监听及恢复。
- `PocketHead/Pocket4ProGimbal.swift`：删除 `backgroundCommandDuration`、`usesBackgroundSmoothing` 和命令时长分支，统一使用已有前台命令时长。
- `PocketHead/Info.plist`：删除 `BGTaskSchedulerPermittedIdentifiers` 及仅含 `processing` 的 `UIBackgroundModes`。
- Xcode 工程显式维护文件，需同步删除旧源码引用和编译项，加入新源码。
- `README.md`：更新功能表、运行说明和技术路径，清除后台/锁屏续跑的旧承诺。

Apple 明确说明 `BGContinuedProcessingTask` 的进度由系统以实时活动显示，故需移除任务本身。[Apple 后台任务文档](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtask)

### 保护层和状态

在整个 `NavigationStack` 之外添加根层 `ZStack`/overlay，覆盖导航栏和安全区。保护时对底层关闭 hit testing，用 `accessibilityHidden` 隔离辅助功能焦点。蒙层建议采用接近纯黑背景、简短状态和中央长按按钮；通过屏幕亮度 API 实际降亮度。

新增轻量状态结构负责保护状态、触摸计时、长按取消及过期任务判定；`@MainActor` 显示控制器负责当前窗口屏幕、常亮、亮度、延迟任务和统一退出。保护视图只发送触摸/长按事件，头追模型继续负责姿态和控制。显示操作不放入现有约 25 Hz 的头追循环。

```text
前台头追中 → 点击防误触 → 保护中、原亮度、禁用自动休眠
保护中、最后触点结束 3 秒 → 约 1 秒渐暗至低亮度、继续保护和常亮
低亮度 + 任意位置按下 → 当次触摸立即恢复亮度，继续保护
中央连续长按达到 1.5 秒 → 取消保护、恢复显示设置，头追继续
头追因异常停止 → 取消保护、恢复显示设置，显示已有异常提示
```

使用单调时钟；取消旧延迟任务后还要校验会话版本/截止时间，避免快速触摸或反复进入时旧任务又降暗。触摸进行中禁止降亮度。中央长按须有明确命中范围，移动超限或取消后清零；多点触摸不可绕过中央长按规则。

可先采用 SwiftUI 全屏活动手势与中央长按同时识别；本轮只确认组合能编译。若实机触摸取消、多点触摸或手势竞争无法可靠覆盖，可在保护层文件内用 `UIViewRepresentable` 承接完整触摸序列，维持同一状态接口。不能只用 `onTapGesture`：它无法覆盖按下即恢复和拖动。

### 显示设置恢复

1. 进入保护保存原自动休眠开关，仅在保护期间开启常亮；所有退出路径统一恢复。
2. 每次从正常亮度降暗前读取并保存当时亮度；已降暗时不得再次覆盖保存值。
3. 任意触摸开始、退出保护、头追停止、页面关闭和最小后台清理时恢复保存值、取消计时；清理可重复调用。
4. 在主线程从当前窗口取得屏幕，不依赖全局 `UIScreen.main` 或失效窗口。

Apple 要求在无需常亮时复位 `isIdleTimerDisabled`。[Apple 常亮文档](https://developer.apple.com/documentation/uikit/uiapplication/isidletimerdisabled)

`brightness` 支持主屏幕，范围为 0 到 1。Apple 说明修改可能持续到设备锁定，即使应用已经关闭。因此必须主动恢复，不能依赖视图销毁或系统自动恢复；强杀/崩溃时不能保证应用能清理。[Apple 亮度文档](https://developer.apple.com/documentation/uikit/uiscreen/brightness)

### 系统边界

- 蒙层只保护应用内控件；常亮阻止自动休眠，无法阻止电源键主动锁屏。
- `defersSystemGestures(on:)` 可让应用手势优先，但不代表禁用回桌面、控制中心或通知中心。系统弹框、来电等也不在应用蒙层内。[Apple 系统手势文档](https://developer.apple.com/documentation/uikit/uiviewcontroller/preferredscreenedgesdeferringsystemgestures)
- 长按可配置最短时长与最大移动距离；完成、提前结束、取消与活动监测的事件顺序仍需实机验证。[Apple 长按文档](https://developer.apple.com/documentation/swiftui/view/onlongpressgesture(minimumduration:maximumdistance:perform:onpressingchanged:))
- 降亮度有助于减少屏幕负担，头部采样、无线链路和控制仍持续运行，不承诺具体耗电降幅。

### 关键测试

| 场景 | 预期 |
| --- | --- |
| 空闲 2.9 秒/3 秒 | 前者原亮度，达到阈值只降暗一次；常亮保持 |
| 降暗后点空白、滑动、中央长按 | 按下即恢复，不穿透；中央长按无需先唤亮 |
| 任意位置按住超过三秒 | 触摸期间不降暗；仅中央有效长按能取消 |
| 短按、松开再按、移出范围、触摸取消、多点触摸 | 不累计短按时间，不误解锁，进度正确重置 |
| 解锁时手指释放 | 不误触底层校准、停止等控件 |
| 快速操作、反复进出保护 | 旧任务不影响新状态，原亮度不丢失 |
| 原亮度 1% / 40% / 100% | 降暗不高于原值，操作/退出恢复该轮保存值 |
| 蒙层下转头、耳机摘戴、相机断连 | 正常持续头追；异常按原规则停机并退出保护 |
| 辅助功能、动态字体、不同尺寸 iPhone | 底层不可操作，中央提示完整；专门验证 VoiceOver 的长按体验 |
| 真机前台静置超过系统自动锁定时间 | 保护期间不自动熄屏，降暗状态仍持续头追 |

常亮和亮度必须用真实 iPhone 验证。后台/锁屏持续控制不列入验收，仅冒烟检查切走时的最小停机和亮度恢复。

### 风险与回滚

- ⚠️ **中风险：手势竞争和触摸穿透。** 用明确层级、底层交互隔离、退出触摸序列隔离；实机决定是否用 UIKit 承接触摸。
- ⚠️ **中风险：亮度与延迟任务竞态。** 集中管理状态、保存原值、幂等清理和会话版本校验；测三秒截止与触摸同时发生。
- ⚠️ **中风险：后台代码清理遗漏。** 同步更新模型、传感器、云台、工程、plist、README；编译和扫描旧标识。
- ✅ **低风险：版本兼容。** 核心 API 覆盖 iOS 17，独立类型检查已通过。
- ✅ **低风险：分支隔离。** 在独立分支 `codex/foreground-touch-guard` 完成源码、文档和自动化验证，集成时按仓库现有 PR 流程合入 `main` 并同步 `dev`。

后续以独立提交实施；回滚前确认工作区干净，按最近提交优先的顺序执行 `git revert <commit>`，验证停机、显示恢复及原功能。不要用硬重置覆盖其他工作。
